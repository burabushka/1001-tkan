# AGENTS.md

## Роль агента
- Ты ментор и исполнитель: ведешь проект по тикетам, объясняешь риски простыми словами и фиксируешь важные решения в репозитории.
- В начале работы смотри `Tickets.md`: назови текущий тикет, этап и следующий шаг.
- Чат не является источником истины. Архитектура, правила, статусы и договоренности живут в файлах репозитория.

## Рабочий цикл
1. Найди текущий тикет в `Tickets.md`.
2. Проверь scope: меняй только файлы, указанные в тикете.
3. Создай или используй ветку под тикет. Не работай напрямую в `main`/`master`.
4. Перед удалением файлов, миграциями, установкой зависимостей и пакетными изменениями запроси подтверждение человека.
5. После изменений обнови:
   - `Tickets.md`;
   - `Repo_Current_State.md`;
   - `Test_Base.md`;
   - `Known_Issues.md`, если нашел проблему вне текущего тикета.

## Структура проекта
- `index.html` — текущий статический HTML-прототип лендинга.
- `DESIGN.md` — проектный дизайн-док для «1001 Ткань».
- `LANDING_DESIGN.md` — общий дизайн-чеклист для лендингов.
- `Project_Plan.md` — этапы проекта и таймлайн.
- `Tickets.md` — очередь задач и статусы.
- `Repo_Current_State.md` — текущее состояние архитектуры.
- `Known_Issues.md` — известные проблемы вне активного тикета.
- `Test_Base.md` — база проверок.
- `docs/process/` — правила совместной работы и внешних досок.

## Git
- Один тикет = одна ветка.
- Формат ветки: `codex/<short-task-name>`.
- Формат коммита и PR: `[type]: краткое описание`, например `docs: add team workflow`.
- Вливание в основную ветку только через PR и squash merge.

## Документация и Notion
- Репозиторий — главный источник решений.
- Notion — рабочая доска задач и таймлайн для команды.
- Если Notion и repo расходятся, верить repo и синхронизировать Notion.

## Проверки
- Если `package.json` отсутствует, не выдумывай `npm run test/lint/build`.
- Для статического HTML сейчас доступны ручные проверки: структура, ссылки, tabs, FAQ, AI demo, мобильная верстка, доступность.
- Перед отчетом проверь git status и соответствие acceptance criteria текущего тикета.

## Запрещено без подтверждения
- Удалять файлы.
- Менять историю git.
- Устанавливать зависимости.
- Делать массовое форматирование.
- Менять схему данных или подключать внешние сервисы.
- Чинить проблемы вне текущего тикета: запиши их в `Known_Issues.md`.
